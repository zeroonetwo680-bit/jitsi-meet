## Goal

1. **Nobody enters Jitsi without an Abaqera account.** Students too: no more anonymous guests. Everyone joins with a JWT the Abaqera API issues after the person signed in with their Abaqera username and password.
2. **Students cannot create a meeting link.** Only trainers and staff can create a lecture. Room names are generated by the API (server side), never by the apps.

## What the Jitsi side will change (after your answers)

* `ENABLE_GUESTS=0`: a visitor without a valid token is refused.
* Optionally `TOKEN_AUTH_URL` so a browser visitor without a token is sent to the Abaqera login page instead of seeing an error (needs answer 3).
* Students get tokens with `moderator: false`, bound to one room through the `room` claim.
* Nothing in the Jitsi server can tell "who may create a room" by itself: any valid token can open the room named in its `room` claim. So the rule is enforced by the API: it only issues a token for a room that a trainer/staff member created, and only to people allowed in it.
